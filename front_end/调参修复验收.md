# 人格调参修复与验收

手机与电脑使用相同的观测台接口。人格及心理参数现在统一交给心理插件保存，随后立即同步核心，避免下一次心跳读回旧值。参数面板与滑块显示后端确认的实际值；保存失败时显示具体原因。

## 更新范围

- 核心插件：`plugins/astrbot_plugin_shihai/main.py`
- 心理插件：`plugins/astrbot_plugin_shihai_psyche/main.py`、`psyche/profile.py`
- 观测台：`front_end/识海心智观测台.html`、`front_end/serve.py`

运行环境需要同时更新核心、心理插件及观测台，并重新加载两个插件、重启观测台服务。Flutter 使用服务端网页，无需为此次修改重新打包。保留现有配置和状态文件，不通过清空数据或修改人格初值解决问题。

兼容规则：心理插件停用、但存在旧的 `psyche_state.json` 时，拒绝人格/心理调参并提示先启用心理插件；没有旧文件时保留核心独立调参。`g_*` 目标仍按原有动力学变化。

## 自动验证

在仓库根目录使用已安装 jieba 的 Python 运行：

```powershell
python -B -m unittest discover -s plugins/astrbot_plugin_shihai/tests -v
python -B -m unittest discover -s front_end/tests -v
node front_end/tests/test_tuning.js
```

测试使用临时状态、框架和 HTTP 替身，不启动 QQ、模型或真实服务。覆盖两次心跳、重新加载后的恢复、两种调参工具、表达层读取、保存失败、旧文件保护，以及网页保存确认与延迟响应。

## 录屏前现场验收

1. 确认核心、心理插件都启用；手机和电脑连接同一观测台服务。
2. 记录外向性 E 的当前值，再在手机上修改。等待“已保存并生效”。
3. 电脑刷新观测台，确认滑块、参数面板、状态观测中的 E 一致。
4. 等待至少两次心跳（默认共 120 秒），切换页面再返回，确认 E 没有恢复旧值。
5. 重新加载核心与心理插件，再刷新两端，确认恢复修改后的值。
6. 使用两种调参工具分别调整一次，确认观测台立即同步。验证完后恢复录屏所需参数。

代码层测试不替代手机与实际部署环境的现场验收。外向性影响念头积累速度，不能把一次调参解释为立刻主动发送消息。
