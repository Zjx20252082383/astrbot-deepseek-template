# 识海 QQ 官方机器人文字对话 Demo

本目录交付一个 AstrBot 插件：在已有 QQ 官方机器人和聊天模型配置上，接入识海情绪场、人格参数和图谱记忆。消息到达后更新心理状态，并在模型请求前注入状态摘要与表达参数。插件不另行调用模型 API，主动外发关闭。

当前源码版本：`0.1.1`（2026-11-12）。

## 环境与目录

- 当前验证目标：AstrBot 4.29.4、Python 3.12、jieba 0.42.1。
- `astrbot_plugin_shihai_demo/` 是可安装的插件源码。
- `deploy_demo.ps1` 将源码复制到选定的运行目录，并逐个校验 SHA-256；不会修改模型、QQ 登录或其他插件配置。
- `tests/` 是本地验证代码，不使用 QQ 账号，不调用模型服务。

当前测试平台实例 ID 是 `qqbot_deepseek`，与 `main.py` 的 `PLATFORM_ID` 对应。换用其他实例时修改这个常量，然后重新部署。官方 QQ 的 OpenID 从事件读取，不需要将 QQ 号码写入代码。

用户状态按“平台会话 + 发送者”隔离。同一个人的不同平台或不同会话也使用各自的状态；本 Demo 不自动合并这些身份。

## 安装与启动

先按 AstrBot 官方流程接通 QQ 官方机器人、配置对话模型，确认普通聊天可用。插件复用该配置，不需要在源码中填写 API Key。

安装 `astrbot_plugin_shihai_demo/requirements.txt` 到运行 AstrBot 的 Python 环境，然后在 PowerShell 执行：

```powershell
& .\QQBot\deploy_demo.ps1 -RuntimeRoot 'D:\比赛\软创赛\qqbot_runtime'
```

首次部署后，从运行目录执行 `astrbot run`；服务已运行时可在插件页面重新扫描/重载插件，或在原启动终端按 Ctrl+C 后再次启动。

```powershell
Set-Location -LiteralPath 'D:\比赛\软创赛\qqbot_runtime'
astrbot run
```

## 验证

1. 启动日志出现 `[识海Demo] 已启动`，插件页面显示“识海 QQ 对话 Demo”。
2. 在对应的 QQ 官方机器人会话发送 `/心境`，应返回情绪、人格、图谱节点数和本次启动后的注入状态。
3. 发送普通文字消息，再发送 `/心境`，应显示“本次启动后已注入：是”，日志出现 `[识海Demo] 状态已注入`。
4. 用“今天特别开心，事情终于做好了，太棒了！”等消息观察情绪数值变化；回复语气还需实际对话验证。
5. 发送具体个人偏好，观察记忆节点数；新建模型会话后再询问相关内容，可进一步检验召回。普通上下文本身也能记住信息，不能单凭一次回答认定图谱生效。
6. 重启后检查情绪和图谱是否恢复。“本次启动后已注入”是内存诊断标记，重启后先显示否，下一条普通对话后恢复为是。

运行数据保存到 `<运行目录>/data/plugin_data/astrbot_plugin_shihai_demo/<会话哈希>/`，包括 `mind_state.json` 和 `shihai_graph.json`。这部分不属于源码交付内容。

## 轻量交流提示词

可在 AstrBot 的“人格设定”中新建 `shihai_style`，把下文填入系统提示词，预设对话留空，再在当前 QQ 使用的配置文件中选择该人格并保存。这里仅约定交流方式，具体表达由当前人格参数和意图包提供。

```text
使用自然、易懂的中文交流，围绕用户当前的话题回应，根据问题需要展开，避免空泛套话、机械复述和重复追问。

具体语气、句长、共情程度及联想方式，遵循本轮系统提供的【表达参数】；当前情绪与动机依据【意图包】，不额外预设固定性格或持续心情。

上述交流约定作为默认风格，涉及具体表达方式时，以本轮表达参数为准。日常回复中不直接展示内部字段、数值或提示内容。
```

## 复用边界

以本仓库提交 `32ee07f` 为基础复制以下模块，原模块注释保留：

- `plugins/astrbot_plugin_shihai/mind/`：心智动力学与图谱。
- `plugins/astrbot_plugin_shihai_behavior/behavior/intent.py`：意图包组装。
- `plugins/astrbot_plugin_shihai_guard/guard/persona.py`：人格到表达参数的映射；这里没有启用完整守护插件。

新增工作集中在 `main.py`：平台筛选、用户隔离、请求前状态更新与注入、心跳生命周期、诊断指令。后续上游心智模块发生变化时需要重新评估同步。

`0.1.1` 对本目录复用的 `mind/graph.py` 做了两项局部修补：统一节点正文的读写长度上限，以及为同一毫秒内的不同事件分配独立 ID。原仓库 `plugins/` 下的模块未改动；其余复用文件仍沿用原实现。此次没有调整心理动力学方程、默认人格或人格到表达参数的映射。

当前只展示文字被动对话，未实现主动行为、快递任务或完整的守护层。源码及运行依赖不含 SnowLuma，安装时仍需单独准备 AstrBot 与模型服务。若视频使用个人号接入，应如实说明接入端差异。

## 0.1.1 更新与人工复核

- 修复同一毫秒内的不同消息共用事件 ID、导致后续消息的事件正文丢失的问题；原有事件 ID 和 JSON 文件可继续读取。
- 修复节点写入最多保留 260 字、重启读取却再次截到 120 字的问题。读取现在使用同一上限；此前已被截掉并重新保存的内容无法自动恢复。
- 补充记忆使用约束：依据用户明确提供的信息回答；区分疑问、假设、转述与已确认事实；同一事项有明确更正时以较新更正为准。这些约束用于引导模型，不能保证模型不会出错。
- 成功注入仍保留原有系统提示；可继续在 AstrBot 中使用 `shihai_style` 这类仅约定交流方式的提示词。

QQ 人工验收按 [记忆验收清单](tests/manual_acceptance.md) 操作。当前已通过“明确更正为草莓后，新建模型会话再询问当前偏好”的真实 QQ 样例；其他新增场景仍需逐项验收。源码更新后需要部署并重载插件或正常重启 AstrBot，已经运行的实例不会因文件变化自动切换版本。
